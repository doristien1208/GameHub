# Game Hub (遊戲入口主控制器)

One Node process on the Windows test machine: serves the portal page (the site is called 更萊姆遊戲: config `title`, also the page's built-in default) that lists every game with live status, starts/stops/restarts the games it manages, restarts crashed or unresponsive ones, and takes a game down while `maintenance.txt` is in its folder. Sibling project of `../BnB` (水球大亂鬥), which it manages via BnB's `/healthz` (`version`, `online`, `playing`).

## Constraints
- Node.js 24 (the test machine moved from 22.18.0 to 24 on 2026-10-22; `.nvmrc` pins the exact version), zero runtime dependencies: `scripts/build.mjs` bundles everything into `dist/hub.js` and `dist/service.js`. Don't add npm runtime deps.
- Maintenance is switched only by the `maintenance.txt` file (any letter case) in a game's folder; the user decided against admin-page buttons for it. Its text is the portal notice. The hub waits while `/healthz` reports `playing > 0` (max 15 min).
- Games run detached with stdout/stderr written straight to `logs/<id>.log`; `hub-state.json` keeps each game's wanted state and pid so a restarted hub adopts running games (adoption requires the pid to own the game's port). Never make the hub kill games when it exits.
- `.bat` and `.ps1` files stay plain ASCII with CRLF (`scripts/package.mjs` enforces it); Chinese goes in `deploy/README-DEPLOY.txt`. `install-autostart.bat` runs `autostart.ps1`, which registers the scheduled task "Game Hub" as the installing admin's own account with S4U logon (no stored password, starts at boot without a logon, no time limit), then checks the task is Running and the hub answers before saying Done. Not SYSTEM: on the test machine SYSTEM could not open the game folders (the task ended with result 1 and wrote no log).
- The task runs `node.exe dist\service.js` directly, never a batch loop: a Node.js update sends Ctrl+C to node.exe, and the old `start-hub.bat service` loop then sat at "Terminate batch job (Y/N)?" with nobody to answer, so the task looked Running while the hub was down (2026-10-29, fixed by ending the task by hand). `src/service.ts` ignores Ctrl+C and restarts the hub 5 s after it stops (30 s after exit 2 = port taken or 3 = bad config); a second trigger starts the task every 5 minutes (ignored while it runs). `service.pid` / `hub.pid` let `autostart.ps1` end both (only if the pid is still that node.exe) before replacing or removing the task.
- `hub.config.json` (live config, has the admin password) is gitignored and never in the package; the hub creates it from `hub.config.example.json` with a random password on first run. Keep internal machine details (IPs, other projects' names) out of committed files: the BnB repo is public, and this one may be too.
- On the test machine the hub listens on 4300 (a free port the user checked there); 8080 is already nginx's.
- The game list is the `games` array of `hub.config.json` (the user's "one JSON"): the page draws whatever `/api/status` returns, so adding a game is a config entry plus its thumbnail, never a page change. Don't hard-code games in the page.
- Thumbnails: `image` names a file in `assets/` (200 x 200), served at `/assets/<file>?v=<mtime>`. Only `assets/bnb.png` is committed (drawn by `BnB`'s own pixel-art code); other games' pictures carry internal names and stay out of git.
- YBOX Game Pass (the user's idea, 2026-10-30) is a parody subscription ad: a banner over the list, a "trial ends in 0 days" pop-up, and a pre-roll before 進入遊戲 now and then (chance `promo.preroll`, at most once in 10 minutes, never for Ultimate). Plans, fake checkout and the three-step cancel are all in the page; nothing is collected, the plan only lives in localStorage. Every "not today" is fake on purpose (the user's call): the banner's ×, the pop-up's 下次再說 and the trailers' 今天不再顯示 only close it until the page is opened again, and what comes back says you asked. Copy is built in (`DEFAULT_PROMO` in `src/config.ts`) and the optional `promo` block of `hub.config.json` overrides it. The logo is a Y in a hexagon drawn in the page: never borrow a real console brand's logo, colours or type.
- Game trailers: any mp4/webm in `assets/pv/` pops up as an ad (muted autoplay, one per page load picked at random but never the one that browser saw last; 今天不再顯示 is fake on purpose, the user's call: it only closes the window and the next one says "您今天已選擇不再顯示"), matched to the game whose id starts the file name, ignoring letter case, `-` and `_` (`bnb-pv.mp4` → `bnb`, `Space_Race_PV_30s.mp4` → `space-race`). Colleagues drop files there themselves, so no config. Videos are streamed with HTTP ranges (`sendVideo` in `src/server.ts`). Only one ad is on screen at a time.
- The portal is black-and-white cyberpunk on purpose: greys plus one colour, the green blinking light of a running game (the user asked for it); other states are told apart by fill / outline / hazard stripes / motion, thumbnails grey until a playable game is hovered. No light theme. The cards show no running time (the user removed it) and the portal has no GitHub links.

## Commands
- `npm run dev` (reads ./hub.config.json), `npm test`, `npm run typecheck`, `npm run package` → `release/game-hub/`

## Layout
- `src/game.ts` state machine per game (running / starting / unresponsive / stopping / stopped / crashed / draining / maintenance / external / offline)
- `src/hub.ts` all games + `hub-state.json`; `src/server.ts` page + `/api/status` (public) + admin API (`x-hub-key` header, lockout after 8 wrong passwords per 10 min)
- `src/index.ts` the hub process (exits 0 on a config change for a restart); `src/service.ts` + `src/supervise.ts` the background service that keeps it running (logs to `logs/launcher.log`); `deploy/autostart.ps1` the scheduled task
- `public/index.html` the portal (vanilla JS, rebuilds only cards whose data changed and reuses each thumbnail node)
- `assets/` thumbnails, copied into the package by `scripts/package.mjs`
